# 투 포인터(Two Pointers)

## 한 줄 정의

배열이나 수열에서 두 인덱스를 일정한 규칙에 따라 이동시켜, 모든 조합을 확인하지 않고 원하는 구간이나 원소 쌍을 찾는 탐색 기법이다.

## 언제 사용하는가

- 정렬된 배열에서 합이 특정 값인 두 원소를 찾을 때
- 양수로 이루어진 연속 구간의 합을 다룰 때
- 두 정렬 배열을 병합하거나 비교할 때
- 완전 탐색은 `O(n²)`이지만, 포인터를 한 방향으로만 움직일 수 있을 때
- 현재 상태에 따라 어느 포인터를 이동해야 하는지가 명확할 때

값에 음수가 섞인 연속 구간 합 문제는 합의 증감 방향이 일정하지 않으므로 단순 투 포인터를 바로 적용하기 어렵다.

## 핵심 아이디어

두 포인터를 계속 처음으로 되돌리지 않고 한 방향으로만 이동한다.

각 포인터가 배열을 최대 한 번씩 지나가므로, 중첩 반복문처럼 보여도 전체 이동 횟수는 보통 `O(n)`이다.

### 대표 패턴

| 패턴 | 포인터 배치 | 이동 기준 |
| --- | --- | --- |
| 양쪽 끝 탐색 | `left = 0`, `right = n - 1` | 합이나 대소 관계 |
| 같은 방향 탐색 | 두 포인터 모두 왼쪽에서 시작 | 구간 조건 만족 여부 |
| 두 배열 병합 | 배열마다 포인터 하나 | 두 현재 원소 비교 |

## 동작 과정

정렬된 배열에서 합이 `target`인 두 수를 찾는 경우:

1. `left`를 배열의 처음, `right`를 마지막에 둔다.
2. 두 값의 합이 `target`보다 작으면 `left`를 오른쪽으로 이동한다.
3. 합이 `target`보다 크면 `right`를 왼쪽으로 이동한다.
4. 합이 같으면 정답을 반환한다.
5. 두 포인터가 만나면 탐색을 종료한다.

## 시간 복잡도

| 구현 방식 | 시간 복잡도 | 공간 복잡도 | 특징 |
| --- | --- | --- | --- |
| 정렬된 배열 양끝 탐색 | `O(n)` | `O(1)` | 정렬 비용은 별도 |
| 같은 방향 구간 탐색 | `O(n)` | `O(1)` | 조건의 단조성이 필요 |
| 두 정렬 배열 병합 | `O(n + m)` | `O(1)` | 결과 배열 공간 제외 |

## Java 예시 코드

```java
class Solution {
    // numbers는 오름차순으로 정렬되어 있다고 가정한다.
    public int[] solution(int[] numbers, int target) {
        int left = 0;
        int right = numbers.length - 1;

        while (left < right) {
            long sum = (long) numbers[left] + numbers[right];

            if (sum == target) {
                return new int[]{left, right};
            }

            if (sum < target) {
                left++;
            } else {
                right--;
            }
        }

        return new int[]{-1, -1};
    }
}
```

## 코드 해설

- `left < right`로 같은 원소를 두 번 선택하지 않게 한다.
- 배열이 정렬되어 있으므로 합이 작을 때 `left`를 옮기면 합을 키울 수 있다.
- 합이 클 때 `right`를 옮기면 합을 줄일 수 있다.
- 두 정수의 덧셈이 넘칠 수 있으므로 합은 `long`으로 계산한다.
- 배열이 정렬되어 있지 않다면 정렬 비용 `O(n log n)`이나 해시 기반 풀이를 고려해야 한다.

## 실수하기 쉬운 지점

- 정렬되지 않은 배열에 양끝 포인터 규칙을 적용하는 것
- 음수가 포함된 구간 합에서도 합이 크면 무조건 왼쪽을 이동하는 것
- `left <= right`를 사용해 하나의 원소를 두 번 선택하는 것
- 합을 `int`로 계산해 오버플로우가 발생하는 것
- 정답의 인덱스가 원본 배열 기준인지 정렬된 배열 기준인지 확인하지 않는 것
- 중복 원소가 있을 때 중복 쌍을 제거해야 하는 문제인지 확인하지 않는 것

## 문제 풀이 접근법

1. 완전 탐색으로 가능한 모든 쌍이나 구간을 확인하면 얼마나 걸리는지 계산한다.
2. 한 포인터를 이동했을 때 값이나 조건이 한 방향으로 변하는지 확인한다.
3. `left`와 `right`가 각각 무엇을 의미하는지 정의한다.
4. 각 분기에서 반드시 하나 이상의 포인터가 이동하게 한다.
5. 빈 배열, 원소 하나, 중복 값, 오버플로우를 확인한다.
